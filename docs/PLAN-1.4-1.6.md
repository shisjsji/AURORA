# AURORA 1.4–1.6 可行性方案：质感、花活、音量

> 本文件基于 2026-11 在 17 Pro（pandora）上的两轮实测：CS35L43 双功放（I2C 13-0040/13-0042）与片内 DSP 保护模型、五场景增量系数文件、`ro.config.media_vol_steps=150`、DynamicsProcessing 的 postEq/MBC/inputGain 闲置面。所有条目按「真材实料」标准过滤过：没有 UI 糖，没有名不副实的功能。

> **实施后裁决（1.4.1）**：1.3 密度粘合、1.4 对话聚焦、3.1 响度守卫、3.2 响度最大化 LMH 四项上机后全部撤下。原因分别是：全频段粘合压缩把九套预设压成了同一种「更密」的听感；对话聚焦对 1.2–3.5 kHz 的 3:1 压缩吃掉的能量大于它给的 +2 dB 倾斜，且与人声清晰预设重复；响度守卫在感知响度顶格时被同一 1000 mB 上限吃掉，实际只表现为常驻 ±4 dB 的曲线漂移；LMH 补的增益被限幅器收紧抵消，听不出「更响」。以下对应小节只作历史记录，不再代表现状。

## 0. 总览

三根柱子，九项。核心判断先说清楚：

- **质感**来自"动态管理"：静态 EQ 已经到头，剩下的提升在"响度不同时曲线不同、信号不同时处理不同"。
- **花活**来自"能量重分配"和"功放包络"：喇叭的物理上限是硬约束，聪明做法是把白费的能量（次声、无效冲程）省下来，投进能出效果的频段；更深的余量在功放自己的保护包络里。
- **音量**来自"响度最大化 + 功放升压"：把 raw gain 推过 1.0 是假音量（一响就削顶），真音量的正路是压缩+补偿增益，以及功放层面的余量。

## 1. 支柱一：整体质感

### 1.1 等响重绘（ISO 226）

- **做什么**：把现在的「音量低于 60% 按固定形状补两端」升级为按 ISO 226 等响曲线族逐档重绘——音量每降一档，按人耳在该声压级下的真实灵敏度差做补偿（20Hz–10kHz 全表编译进引擎，换算到我们的频点）。
- **为什么可感**：低音量下"低频消失、高频发闷"是绝对音感；教科书级补偿一次就能听出"小音量也完整"。
- **实现**：纯数学，`buildGains` 里替换 `applyVolumeCompensation`；曲线表按 10dB 声压级分档插值。
- **风险**：低。唯一注意点：补偿上限仍受 preamp/限幅器约束，不额外抬峰。
- **第一版即可交付**。

### 1.2 动态低音管理

- **做什么**：把 MBC 剩余的 5 个压缩器启用起来，低频段（<200Hz）做"随电平收紧"的压缩：小音量放开、大音量收紧，低频永远"紧"不"轰"。曲线上的低频提升量可以更大，因为压缩器会在大电平处接管。
- **为什么可感**：现在大音量下低频的"轰"和破音，本质是冲程失控；动态管理让同一套曲线在大音量下更体面、小音量下更足。
- **实现**：MBC band 0 已有（120Hz ratio 2），扩为多段：如 60Hz/150Hz 各一段，ratio 2–3、threshold 随音量联动。引擎参数活。
- **风险**：低。MBC 写入路径已验证多年。
- **第一版即可交付**。

### 1.3 密度粘合（轻压缩）

- **做什么**：全频段轻比例压缩（1.5:1，慢起控）做"响度粘合"——手机小喇叭的"质感"一半来自密度；过载的瞬态被温和整合后，声音显得更大更整。
- **为什么可感**：A/B 是"散"与"实"的差别，是"质感"最直接的来源。
- **实现**：MBC 中高频段各一段轻压缩 + 后级限幅器兜底。引擎参数活。
- **风险**：低；比例小、起控慢，不改变音色只改变密度。
- **第一版即可交付**。

### 1.4 对话聚焦

- **做什么**：人声模式：1–3kHz 段压缩提密度、200–400Hz 轻收、4kHz 存在感；播客/视频台词清晰度显著提升。
- **实现**：MBC 中频段 + preEq。已在 1.4 候选。
- **风险**：低。

## 2. 支柱二：花活

### 2.1 超低频能量重分配（本轮方案的头牌花活）

- **做什么**：手机放不出 40Hz 以下的次声，但播放器会把这些能量送进功放——它们不产生声音，只消耗冲程和功率。方案：
  1. **次声管理**：对 45Hz 以下做陡峭高通（省下冲程预算）；
  2. **预算再投资**：把省下的余量投入 60–100Hz 的真实低频区（17 Pro 的 N*Bass 封闭腔在这个区间是能出效果的）；
  3. **内容自适应**：检测低频能量，Bass 稀疏的内容不硬抬（避免"糊"），Bass 密集的内容才释放预算。
- **为什么可感**：这是"用物理做加法"——低频存在感明显加深，且不增加破音风险（冲程预算守恒）。
- **实现**：需要在 80Hz 以下加频段 → `DynamicsProcessing` 自定义 Config（3 参构造器，preEq 频段数扩展），带"设备拒绝非默认 Config"的回退路径。**这是本方案唯一需要动引擎构造路径的功能，1.5 做**。
- **边界**：高通斜率与提升量按 `device pack` 每机型一套；先在 17U/17P 两只喇叭上做冲程测试再放参数。
- **风险**：中（自定义 Config 的兼容性，已有回退设计）。

### 2.2 火力档：功放保护包络（最深的花活，Stage 1）

- **已探明的事实**：17 Pro 的在役功放是 CS35L43 ×2；厂商在 `/odm/firmware/` 按场景（music/movie/video/voice/navigation）下发五套保护增量，**厂商自己就在按场景调整保护激进度**——这就是安全余量存在的直接证据；两颗功放的 DSP 内存有 850 个寄存器不同（上下喇叭的个体标定）。
- **做什么**：解析五套场景增量的参数块 → 画出厂商包络（各参数的五档数值范围）→ 在包络内做一档"音乐火力"：低频保护阈值放到厂商 music 档的极限内、升压/限幅余量小幅放宽。通过 Magisk bind-mount 替换系数文件实现（驱动走正规加载路径，无寄存器竞态）。
- **边界（四条硬线）**：
  1. 改动值不越过厂商五档的并集极值；
  2. 删除 overlay 即完全还原；实验期零持久寄存器写入；
  3. 依赖 CS35L43 片内温度遥测持续监控，超温回退；
  4. 开发者设备先泡两周，之后才以默认关闭的实验包下发。
- **风险**：中高（物理损伤风险由四条边界兜底，但你自己的机器先承担验证）。
- **工作量**：大（WMDR 块格式解析 + 参数语义映射 + 听感标定）。
- **1.5 立项，1.6 落地**。

### 2.3 心理声学低频增味（诚实近似）

- **做什么**：在 120–200Hz 的谐波区做低频内容的"存在感"加权，微砍 60–80 的真实低频峰——利用"缺失基频"幻觉让耳朵"听到"更低的低音。
- **诚实说明**：真正的谐波生成器（MaxxBass 式）需要 waveshaper，AOSP 会话音效没有这个积木。这一项是"低频修辞"，不是"凭空下潜"，UI 和文案里必须如实标注。
- **实现**：preEq 曲线组合，零新架构。
- **风险**：低。

## 3. 支柱三：音量

### 3.1 响度守卫（逐曲归一）

- **做什么**：引擎用 Visualizer 按会话监测 RMS（250ms 轮询、EMA），自动微调 **inputGain**（±4dB，0.5dB 步进限速）：过响的歌压下来、过轻的抬起来，切歌不再"炸一下/闷一下"。
- **实现**：DP 的 inputGain（闲置参数）+ Visualizer（system_server 引擎线程创建，无权限障碍）。已在 1.4 候选。
- **风险**：低。

### 3.2 响度最大化 LMH

- **做什么**："免提音量感"：多段轻压缩 + 补偿增益，把整体 RMS 抬 3–6dB，峰值由限幅器兜住——感知响度显著提升而数字电平不越界。这就是商业"音量增强"的真实实现方式。
- **为什么诚实**：raw gain 推过 1.0 会让 DAC 削顶（用户听到的是"炸"不是"响"）；LMH 是唯一不牺牲安全的响度路径。
- **实现**：MBC 全段轻压缩 + `LoudnessEnhancer`（现有 0–5dB 扩到 0–10dB）+ 限幅器联动。引擎参数活。
- **风险**：中（压缩感需要标定，"闷"和"响"一线之隔）。
- **第一版即可交付**。

### 3.3 系统音量（诚实结论）

- **能做的**：系统音量内部已是 150 步（按键步进 10），音量键步进细化是框架钩子活，**但这不是"增强音量"**。Mixer gain 上限 1.0，超出即削顶——"系统音量增强"的正路只有两条：LMH（3.2）和功放升压（2.2 的一部分）。
- **不做的**：hook 音量曲线强行放大（假音量，必削顶）。
- **结论**：音量篇的交付 = 3.1 + 3.2 + 功放升压档。

### 3.4 感知响度扩展

- **做什么**：现有「感知响度」0–5dB 扩到 0–10dB，联动限幅器阈值（大补偿时限幅器加严），防止"越开越破"。
- **实现**：`LoudnessEnhancer` 参数范围 + 限幅联动逻辑。
- **风险**：低。

## 4. 实施序与验收

**1.4（全部引擎参数层，无需等待硬件工作）**
1.1 等响重绘 · 1.2 动态低音管理 · 1.3 密度粘合 · 1.4 对话聚焦 · 3.1 响度守卫 · 3.2 LMH · 3.4 感知响度扩展

**1.5（硬件包）**
2.1 超低频能量重分配（自定义 Config）· 2.2 Stage 0：五场景增量全解析 + 扬声器体检页（读寄存器）· 3.3 音量键步进细化

**1.6（硬件深水区）**
2.2 Stage 1 火力档（系数 overlay，开发者设备先泡两周）· 后续 LKM 自动化（利用 android-kernel-lkm 工作流）

**验收指标（每项都要过）**
- A/B 盲听：曲线差异可辨、无新伪影（破音/泵动/齿音）；
- 电平测量：`aurora_backend_bands` + dmesg，峰值 ≤ −1 dBFS，RMS 提升幅度记录在案；
- 回归清单：沉浸声开/关、低音量/满音量、低码率内容（抖音/游戏）、铃声边界。
