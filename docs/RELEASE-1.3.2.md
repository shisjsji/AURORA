# AURORA 1.3.2

这一版治沉浸声（空间音频）路径上的杂音——多机型反馈「有杂音、关掉系统沉浸声会好」的根因修复。

## 一、电路复原（取证来源：device/ 的 AudioFlinger dump + AOSP 源码）

**正常路径**（沉浸声关）：

```
App 音轨(session) → 【AURORA：preEq 六段 + MBC + Limiter】(会话级)
                  → AudioOut_D 混音
                  → 【DAP_offload(Dolby) → MiSound】(session 0 输出链)
                  → 音量 → HAL → 扬声器
```

**空间音频路径**（沉浸声开）：

```
App 音轨(session) → 【AURORA】(会话级，随会话挂到 5D 线程)
                  → AudioOut_5D 混音（上混多声道 0x2d63f）
                  → 【miSpatializer】(线程级链上唯一的效果器：多声道→双声道 HRTF 渲染)
                  → 音量 → HAL(24bit) → 扬声器
```

三条事实叠出杂音：

1. **沉浸声路径上小米的保护链整条不在**。AudioOut_5D 的线程级链只有一个 miSpatializer；MiSound 与 DAP_offload 都挂在正常输出线程的 session 0 链上，空间化后音乐不再经过它们——AGC、响度管理、扬声器保护全部缺位。
2. **HRTF 渲染器自带补偿增益，且在限幅器下游**。串扰消除损失能量后渲染器要补回来，这份增益发生在我们会话级限幅器之后——限幅器无法为它留顶。−6 dBFS 的上限 + 渲染增益 → 顶穿 24bit 数模转换 → 数字削顶。这就是「满音量破和沙」与「关掉沉浸声会好」的机理。
3. 1.3.1 之前限幅器从未生效（构造器签名 bug），这条无保护路径上连我们自己这层保险也是缺的。

另一类反馈「最小音量炸音」与此不同：音量在效果链之后才衰减，小音量下 DAC 不可能削顶——那是旧默认砖墙限幅器（10:1/1ms）的可闻调制伪影，1.3.1 的真限幅器（6:1/5ms/80ms）已大幅缓解。

## 二、修复

引擎逐会话读取系统的空间化标记：`AudioPlaybackConfiguration.isSpatialized()`（SystemApi，真机 framework 的 DEX 中已验证存在；反射取不到时静默关闭该特性）。

- 被空间渲染的会话：限幅器阈值下探 `SPATIAL_HEADROOM_DB = 4` dB（可覆盖约 +8 dB 的渲染增益），**曲线形状不变**；数学上满刻度峰 −10 dBFS 阈值、6:1 下落至 ≈−8.3，加 8 dB 渲染增益仍留 0.3 dB 余量。
- 正常路径会话不受影响（有 MiSound/DAP 保护在）。
- 会话在两条路径间切换（用户开关沉浸声）：`AudioEq.applyLimiter()` 热更新限幅器，不重建效果器——沿用「全程只 open 一次」的原则。
- 引擎回执带「沉浸声路径：限幅器已加严 4 dB 防空间渲染削顶」，用户与反馈日志都能看见。

## 升级须知

**改了 system_server 侧引擎，装完必须重启设备。** 重启后开沉浸声播放任意音频，诊断页状态条出现「沉浸声路径：限幅器已加严」即修复生效； 杂音应消失。若 4 dB 余量不足（仍偶发杂音），下一个可调点是 6 dB（引擎常量）或给空间化会话叠加曲线预衰减。
